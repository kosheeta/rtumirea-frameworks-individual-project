# Сервис учёта использованных источников

## Назначение

Приложение для учёта источников, используемых в научных и учебных
исследованиях. Позволяет фиксировать источники и их авторов,
отслеживать актуальность источника и формировать библиографическую
запись для списка литературы.

Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django.

## Используемые технологии

- Python 3.10+;
- Django 5.2 — веб-фреймворк;
- HTML, CSS и Bootstrap 5.3 — разметка и оформление страниц;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Целевая аудитория

Студенты, аспиранты и преподаватели, ведущие исследовательскую работу
и нуждающиеся в структурированном учёте источников для своих работ.

## Предметная область

Учёт использованных источников литературы: у каждого источника есть
автор, название, год публикации и ссылка; источники группируются в
рамках конкретного исследования, а для итоговой работы требуется
проверять источники на полноту данных и оценивать их актуальность.

## Основные сущности

- Пользователь (студент или преподаватель, который ведёт исследования
  и добавляет источники)
- Исследование (научная или учебная работа, для которой собираются
  источники)
- Источник (статья, книга, публикация со ссылкой)
- Автор (автор источника)

## Возможности

- учёт пользователей (добавление, поиск по имени или email);
- учёт исследований пользователя и относящихся к ним источников;
- добавление и удаление источников;
- поиск источников по автору или названию;
- фильтрация и сортировка источников по году публикации;
- проверка полноты данных источника;
- формирование библиографической записи источника;
- оценка актуальности источника по его возрасту;
- статистика по источникам исследования (количество, средний год
  публикации, число актуальных и устаревших источников).

## Классы

### User — пользователь

Атрибуты: `id`, `name`, `email`.

Методы:

- `from_data(data)` — classmethod, создаёт пользователя из данных JSON;
- `is_email_valid(email)` — staticmethod, проверка email;
- `__str__()` — строка вида `Имя <email>`.

### Research — исследование

Атрибуты: `id`, `user` (объект `User`), `title`, `description`.

Методы:

- `belongs_to(user)` — принадлежит ли исследование пользователю;
- `__str__()` — название, описание и владелец.

### Source — источник

Атрибуты: `id`, `research` (объект `Research`), `user` (объект `User`),
`author`, `title`, `year`, `url`.

Методы:

- `is_valid(author, title, year)` — staticmethod, проверка полноты данных;
- `get_age()` — возраст источника в годах;
- `get_relevance()` — актуальность источника;
- `format_citation()` — библиографическая запись;
- `__str__()` — библиографическая запись.

## Взаимодействие объектов

```
Source
 ├── research → Research
 │               └── user → User
 └── user → User
```

Исследование ссылается на пользователя-владельца, источник — на
исследование и на пользователя, который его добавил. В JSON хранятся
только идентификаторы (`user_id`, `research_id`), при загрузке
`storage.py` находит нужные объекты и восстанавливает связи.

Функции обработки коллекций (`add_*`, `find_*`, сортировка, фильтрация,
статистика) остались обычными функциями в модулях пакета `models`.

## Страницы веб-интерфейса

- `/` — главная страница с навигацией (`homepage.views.index`);
- `/researches/` — список исследований (`researches_list`);
- `/researches/<slug:slug>/` — исследование, его источники
  и статистика (`research_detail`);
- `/sources/` — список источников с оценкой актуальности
  (`sources_list`);
- `/sources/<int:source_id>/` — источник и библиографическая запись
  (`source_detail`);
- `/users/` — список пользователей (`users_list`);
- `/users/<int:user_id>/` — пользователь и его исследования
  (`user_detail`);
- `/sources/search/?q=...&year=...` — поиск источников по автору или
  названию и году (`sources_search`);
- `/statistics/` — статистика по источникам (`homepage.views.statistics`).

Если объект с указанным id не найден, возвращается страница с кодом 404.
Для неизвестных адресов используется собственный обработчик `handler404`.

## Шаблоны и статические файлы

View-функции готовят контекст и вызывают `render()`, HTML формируется
в шаблонах Django:

У каждого приложения своё пространство имён URL (`app_name`), ссылки

## База данных и Django ORM

Веб-часть работает с базой через Django ORM. Модели:

- `users.models.User` — `name`, `email` (уникальный);
- `researches.models.Research` — `user` (FK на `User`,
  `related_name="researches"`, `PROTECT`), `title`, `description`;
- `sources.models.Source` — `research` (FK на `Research`,
  `related_name="sources"`, `CASCADE`), `user` (FK на `User`,
  `related_name="sources"`, `PROTECT`), `author`, `title`, `year`, `url`;
  методы `get_age()`, `get_relevance()`, `format_citation()`.

Таблицы создаются миграциями (`*/migrations/0001_initial.py`):

```
python manage.py migrate
```

Данные переносятся из базы ПР7 `data/sources.sqlite` в базу Django
`db.sqlite3` (стратегия: новые таблицы Django + перенос данных с
сохранением id и связей):

```
python db/inspect_source_db.py
python db/import_sqlite_to_orm.py
```

Скрипт можно запускать повторно — используется `update_or_create()`.

Операции ORM в представлениях:

- списки и получение по id: `select_related()`, `get()`,
  `filter(pk=...).first()`;
- фильтрация: по исследованию и пользователю (`research_id`, `user_id`),
  по году (`year__gte`), исключение устаревших (`exclude(year__lt=...)`);
- поиск: `Q(title__icontains) | Q(author__icontains)`,
  `author__istartswith`, `title__icontains` для исследований;
- сортировка через словарь разрешённых полей, в том числе по полям
  связанных моделей (`research__title`, `user__name`);
- обратные связи: `research.sources`, `user.researches`, `user.sources`;
- агрегирование: `aggregate(Count, Avg, Min, Max)`, `annotate(Count(...))`,
  группировка по актуальности через `Case/When` + `values().annotate()`,
  условие на группу `annotate(Avg).filter(...)`;
- постраничный вывод списка источников (`Paginator`, по 5 на странице).

Списки исследований и источников принимают GET-параметры (`q`, `user`,
`research`, `year`, `fresh`, `sort`, `page`), некорректные значения
не приводят к ошибке.

В SQLite `LIKE` не учитывает регистр кириллицы, поэтому в
`homepage/sqlite_like.py` для соединения регистрируется своя функция
`like`.

Предыдущая реализация на `sqlite3` (`sql/`, `db/database.py`,
`db/import_json.py`, `data/sources.sqlite`) оставлена в проекте как
этап ПР7.

## Формы (ПР11)

- `sources.forms.SourceFilterForm` (`forms.Form`) — фильтр списка
  источников по GET-параметрам: исследование, пользователь, статус,
  диапазон лет, «без устаревших», сортировка. Проверки: год не в будущем
  (`clean_year_to`), начальный год не больше конечного (`clean`).
- `sources.forms.SourceForm` (`ModelForm`) — создание и редактирование
  источника. Валидаторы в `sources/validators.py` (год от 1450 до
  текущего, у автора есть фамилия и нет цифр), `clean_title()` убирает
  лишние пробелы, `clean()` запрещает добавить один и тот же источник
  в исследование дважды (без учёта регистра, текущий объект при
  редактировании не считается дубликатом).
- `researches.forms.ResearchForm` (`ModelForm`) — создание и
  редактирование исследования с загрузкой обложки (`ImageField`,
  до 2 МБ, файлы в `media/researches/`).

Страницы:

- `/sources/create/` — новый источник (из исследования поля исследования
  и пользователя заполняются заранее);
- `/sources/<id>/edit/` — редактирование;
- `/sources/<id>/exclude/` — исключить или вернуть источник (только POST);
- `/sources/<id>/delete/` — подтверждение и удаление (POST);
- `/researches/create/`, `/researches/<slug>/edit/` — исследование.

Все POST-формы содержат `{% csrf_token %}`, данные сохраняются только
после `is_valid()`, после сохранения выполняется redirect и выводится
сообщение (`django.contrib.messages`). Отсутствующий объект — 404
(`get_object_or_404`). Поля формы выводятся общим шаблоном
`templates/includes/form_fields.html` с подписями, подсказками и
ошибками, оформление Bootstrap задаётся в `__init__` форм.

Загруженные файлы хранятся в `MEDIA_ROOT = media/` (в Git не попадают),
в режиме разработки раздаются по `MEDIA_URL = /media/`. Нужен Pillow.

## Административная панель

Адрес: http://127.0.0.1:8000/admin/. Суперпользователь создаётся
командой:

```
python manage.py createsuperuser
```

Названия приложений, моделей и полей русские (`AppConfig.verbose_name`,
`verbose_name` в моделях, `LANGUAGE_CODE = "ru-RU"`), заголовки админки
заданы в `sourcehub/urls.py`.

- **Пользователи** — столбцы: имя, email, число исследований и
  источников (через `annotate`, с сортировкой); поиск по имени и email;
  в карточке inline-список исследований пользователя.
- **Исследования** — столбцы: название, владелец, slug; фильтр по
  владельцу; поиск по названию, описанию и имени владельца; в карточке
  inline-список источников; `autocomplete_fields` для владельца.
- **Источники** — столбцы: название, автор, год, статус, исследование,
  пользователь, актуальность; год и статус редактируются прямо в списке
  (`list_editable`); фильтры по статусу, исследованию, пользователю и году;
  поиск; поля сгруппированы `fieldsets`; `short_name` и актуальность только
  для чтения; массовые действия «Отметить как проверенные» и «Исключить
  из исследования»; `list_select_related` убирает лишние запросы.

## Доработки моделей (ПР10)

- `Source.status` — статус на `TextChoices`: новый, проверен, исключён.
  Исключённые источники не учитываются в статистике и счётчиках.
- `Source.short_name` — `GeneratedField` («Автор, год»), считается базой
  данных (`db_persist=True`) и обновляется при изменении автора или года.
- `SourceQuerySet` (менеджер `Source.objects`): `with_related()`,
  `not_excluded()`, `fresh()`, `outdated()`, `with_age()` (через `F`).
- `Research.slug` — англоязычный slug (транслитерация названия), адрес
  исследования `/researches/<slug>/`, `get_absolute_url()` у исследования
  и источника. Для существующих записей slug заполнен в миграции.
- Контекстный процессор `homepage.context_processors.site_counts` выводит
  количество исследований и источников в меню на всех страницах.
- Статистика по статусам: `aggregate(Count(..., filter=Q(...)))`.

## Анализ SQL

При `DEBUG = True` подключён Django Debug Toolbar (вкладка SQL справа на
странице). Списки используют `select_related()`, поэтому связанные
исследования и пользователи загружаются одним запросом с JOIN, а не
отдельным запросом на каждую строку.

## Структура проекта

- `manage.py` — утилита управления Django-проектом;
- `sourcehub/` — настройки Django-проекта (`settings.py`, `urls.py`);
- `templates/` — базовый шаблон и общие фрагменты;
- `homepage/` — главная страница, обработчик 404, статические файлы;
- `researches/`, `sources/`, `users/` — Django-приложения со страницами
  исследований, источников и пользователей (`views.py`, `urls.py`,
  `templates/`);
- `main.py` — консольная версия: меню и пользовательские сценарии;
- `models/users.py` — класс `User` и функции работы с пользователями;
- `models/researches.py` — класс `Research` и функции работы
  с исследованиями;
- `models/sources.py` — класс `Source`, функции работы с источниками
  и статистика;
- `storage.py` — загрузка JSON в объекты и сохранение объектов в JSON;
- `users/models.py`, `researches/models.py`, `sources/models.py` —
  модели Django;
- `db/`, `sql/` — база ПР7 и скрипты переноса данных в ORM;
- `utils.py` — вспомогательные функции безопасного ввода;
- `data/` — JSON-файлы данных (`users.json`, `researches.json`,
  `sources.json`);
- `tests/` — автоматизированные тесты pytest (`test_users.py`,
  `test_researches.py`, `test_sources.py`, `test_storage.py`).
